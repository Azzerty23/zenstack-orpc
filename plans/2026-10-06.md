# Plan — `zenstack-orpc` (ZenStack v3 × oRPC v2 beta)

## Status (2026-10-06)

All steps of the initial plan are done, plus several additions. Initial commit `e4480d6` on `main` (not pushed, not published to npm).

- `typecheck`, `test` (113 tests, 13 files, runtime and types), `build` and `lint` pass.
- The example's e2e scripts pass against a fresh server: `e2e:rest`, `e2e:live`, `e2e:browser` (Playwright, two users).
- Details of the shipped API: `packages/core/README.md` and `packages/core/CHANGELOG.md`.

## Goal

A publishable `zenstack-orpc` library: from a ZenStack v3 `SchemaDef`, generate at runtime an idiomatic oRPC v2 router (`2.0.0-beta.42`, pinned), plus typed client and TanStack Query utilities, with an example app.

Sources: the oRPC v2 docs, ZenStack v3 building blocks (`createQuerySchemaFactory`, `@zenstackhq/client-helpers`, runtime plugins, `@zenstackhq/server` error mapping), `olup/zenstack-trpc` (result typing, strict inputs, type tests) and `cf-realtime` (scalable realtime). viiite is only a list of pitfalls to avoid.

## Decisions

- **Monorepo:** bun, turborepo, tsdown, vitest, biome. `packages/core` (published as `zenstack-orpc`), `example/server`, `example/web`.
- **Exports:** `.`, `./openapi`, `./client`, `./tanstack-query`, `./node`, `./s3`, `./plugin-orpc` (+ `plugin.zmodel`).
- **Validation:** ZenStack's `createQuerySchemaFactory`, validated once (ORM validation skipped unless the client restricts inputs more).
- **Out of scope:** ZenStack custom procedures (`$procs`): write oRPC procedures instead.

## Features

| Area | Delivered |
|---|---|
| RPC router | `createZenStackRouter`: 16 CRUD operations per model, `zenstackMeta`, `limits`, model/operation include/exclude |
| Errors | ORM errors → `ORPCError` (`NOT_FOUND`, `UNPROCESSABLE_CONTENT`, `FORBIDDEN`, `BAD_REQUEST`, `INTERNAL_SERVER_ERROR`), `zenstackErrors`, `isZenStackError` on the client |
| REST / OpenAPI | `createZenStackOpenAPIRouter`, JSON GET arguments, `/{id}` routes, compact spec (`ZenStackJsonSchemaConverter`), docs from ZModel (`///`, `@@meta`) |
| Transactions | Sequential `$transaction`, `txRef`, synchronous callback form on the client |
| Live queries | `zenstackLive` plugin (after commit), `$changes` stream with topics derived from queries (ids, foreign keys), authorized once, visibility checks (`@@live(checkVisibility)`), one connection per client, 50 ms batching, resume, `throttle`, live infinite queries |
| Files | `@file(accept, maxSize, cleanup)`, `upload`/`get`/`remove`/`url`/`presign`/`confirm`, fs/memory/S3 storages, `zenstackFiles` cleanup plugin, ETag/Range in REST, `String[] @file` |
| Client | `createZenStackClient`, `createZenStackQueryUtils`, inferred results, strict inputs, composable types (`WithZenStack`, `WithClient`, `WithQueryUtils`) |
| TanStack Query | Invalidation, optimistic updates following `where`/`orderBy`/`take`, infinite queries, SSR hydration (`zenstackHydration`, `connectLive`) |
| ZenStack features | `@@delegate`, views, `@computed`, `@omit`, typed JSON, `Decimal`, `Bytes`, field-level policies, `post-update`, `@fuzzy`/`@fullText` (PostgreSQL) |

## Changes from the initial plan

- Folders: `packages/core` instead of `packages/zenstack-orpc`, `example/*` instead of `apps/*`.
- The example server runs on Node (`tsx`, `@hono/node-server`).
- The ZModel plugin provider is `zenstack-orpc/plugin-orpc`.
- Live queries watch **topics** (id / foreign key equalities) instead of whole models, so unrelated changes send nothing.
- `zenstackLive(schema, publisher)` and `zenstackFiles(schema, storage)` take the schema.
- `@zenstackhq/client-helpers` is bundled into `./tanstack-query` (no ORM in browser bundles).

## Example app

- **Server** (Hono, better-auth, policies, SQLite): `User`/`Session`/`Account`/`Verification`, `Todo`, `Post` (`@@delegate`: `Article`, `Photo` with `image @file`), `Room`/`Message`. `/rpc` (RPCHandler), `/api` (OpenAPIHandler + Scalar), `/api/auth` (better-auth). Local disk storage, or S3 when `S3_BUCKET_URL` is set.
- **Web** (Vite, React, TanStack Router/Query): login, todos (live, optimistic), posts (image upload, live), chat (live infinite query).
